## 2. 收支记录

收支记录指一笔资金进出事件的记录，包含日期、方向、金额、分类等要素（定义见 01 第 5.3 节）。方向为收入 / 支出 / 转账；转账不计入收支统计（01 第 5.3 节记账规则，全套文档统一）。本模块中收支记录的产生有两个入口：手动记一笔、CSV 账单导入（导入规则见《02-资产汇总模块》）。

### 2.1 手动记一笔

**目的**：让用户在一笔消费或收入发生后，以最低操作成本把它记成一条收支记录，并立即反映到统计与预算进度中（对应 01 场景 2）。

**布局**：点击「记一笔」后弹出表单浮层 [Assumption, TBD: 浮层形式]，表单区域自上而下为：

1. 方向分段选择：支出 / 收入 / 转账，默认选中「支出」；
2. 金额输入：大号数字输入框；
3. 分类选择区：常用分类宫格 + 「更多分类」入口；点击某一级分类后进入其二级分类选择（可跳过二级、仅记到一级 [Assumption, TBD: 跳过的交互方式]）；
4. 日期选择；
5. 所属账户选择（选填）；
6. 备注输入（选填）；
7. 「保存」「取消」按钮。

**触发**：用户点击页面常驻的「记一笔」按钮。

**处理规则**：

1. 表单默认值：方向默认「支出」；日期自动填充为当天（01 场景 2）；其余字段为空。
2. 分类可选集合由方向决定：方向为支出时只能选支出分类，为收入时只能选收入分类（两套体系相互独立，见 01 第 5.4 节）；方向为转账时不展示分类选择区（转账不参与分类统计，见本节第 4 条）。
3. 近期使用分类置顶规则：
   - 置顶对象为当前方向（支出 / 收入）下的分类，按「该分类最近一次被保存进一条记录的时刻」倒序排列，取前 [Assumption, TBD: 6] 个在分类宫格中置顶展示；
   - 每次保存（含编辑后保存）一条记录，其分类的使用时刻即刷新为本次保存时刻；删除记录不回退使用时刻 [Assumption, TBD]；
   - 近期使用不足该数量时，其余分类按第 3 章内置清单顺序排列，自定义分类排在内置分类之后 [Assumption, TBD]；
   - 进入某一级分类的二级列表后，二级分类同样按近期使用置顶 [Assumption, TBD]；
   - 转账方向无分类，不参与本规则。
4. 转账方向的处理：方向选择「转账」时，表单展示「转出账户」「转入账户」两个选填选择项（从已创建账户中选择，账户概念见 01 第 5.1 节），替代分类选择区与所属账户项；转账记录不计入收支统计、预算进度与占比图（01 第 5.3 节"转账不产生收支、只改变资金位置"），仅在收支记录列表中可见。
5. 校验规则：

| 校验项 | 规则 | 不满足时的表现 |
|---|---|---|
| 金额 | 必填；为数字；大于 0；小数位不超过 2 位；不超过上限 [TBD] | 「保存」不可用，金额输入框下方提示"请输入大于 0 的金额，最多两位小数" |
| 分类 | 方向为支出 / 收入时必选 | 提示"请选择分类"，未选时「保存」不可用 |
| 日期 | 必填；范围为当天起往前 [Assumption, TBD: 365] 天内，不支持选择未来日期 [Assumption, TBD] | 手动清空后提示"请选择日期" |
| 转账账户 | 转出与转入账户都填写时，两者不能为同一账户 [Assumption, TBD] | 提示"转出与转入账户不能相同" |

6. 保存动作：校验全部通过后「保存」可用；点击后记录生成，金额按两位小数展示（01 第 5.3 节）。

**结果与状态变化**：

1. 保存成功后表单关闭，页面显示"已保存"提示并自动消失 [Assumption, TBD: 2 秒]；
2. 该记录出现在收支记录列表中（当列表当前筛选的周期包含其日期时立即可见）；
3. 该记录立即计入统计：支出记录计入周期支出合计、对应分类已支出、预算进度、占比图；收入记录计入周期收入合计；转账记录不进入任何统计；
4. 若该笔支出使某分类或总预算达到预警梯度，页面顶部提示条与预算卡片内高亮立即出现（与 01 场景 2 完成标志一致，梯度规则见第 5 章）。

**字段定义**：

| 字段 | 必填 | 默认值 | 可选值 / 格式 | 说明 |
|---|---|---|---|---|
| 方向 | 是 | 支出 | 支出 / 收入 / 转账 | 转账不计入收支统计（01 第 5.3 节） |
| 金额 | 是 | 空 | 大于 0 的数字，最多两位小数，上限 [TBD] | 展示时保留两位小数 |
| 分类 | 支出 / 收入方向必填；转账方向不出现 | 无 | 见第 3 章内置清单及用户自定义分类 | 一笔记录仅归一个分类（见 3.3） |
| 日期 | 是 | 当天 | 当天往前 [Assumption, TBD: 365] 天内 | 交易发生日期 |
| 所属账户 | 否 | 空 | 已创建账户中单选 | 账户概念见 01 第 5.1 节；用户尚未创建任何账户时此字段不展示 [Assumption, TBD] |
| 转出账户 / 转入账户 | 否（仅转账方向出现，替代所属账户） | 空 | 已创建账户中单选 | 两者都填写时不能相同 [Assumption, TBD] |
| 备注 | 否 | 空 | 自由文本，上限 [Assumption, TBD: 50 字] | — |
| 数据来源 | —（自动） | 手动录入 | — | 生成后不可修改，在列表中作为来源标识展示 |

**状态**：记录本身无生命周期状态，保存后长期有效，直至被编辑或删除。表单有三种交互状态：填写中、校验不通过（行内提示）、已保存（表单关闭并显示成功提示）。

**异常场景**：

| 场景 | 处理 |
|---|---|
| 金额输入非法（空、0、负数、三位小数） | 「保存」不可用并给出行内提示 |
| 用户未创建任何账户 | 所属账户字段不展示，其余不受影响，可正常保存 |
| 补记很久以前的记录 | 日期选择范围有限（[Assumption, TBD: 365] 天），更早日期无法选择 |
| 保存时分类已被停用（另一处同时操作分类） | 以当前可选分类列表为准，需重新选择 [Assumption, TBD] |

### 2.2 CSV 账单导入记录进入收支记录与预算统计

**目的**：让用户通过导入支付宝 / 微信账单或银行流水得到的记录，与手动记录合并为统一的收支记录，并自动进入周期统计与预算进度（对应 01 场景 3；解决 01 问题 P2"账单互不覆盖"）。

**布局**：导入的操作流程、预览列表、分类映射与去重交互均在《02-资产汇总模块》定义的导入界面中完成，本文档不重复定义。导入完成后，生成的记录出现在本模块的收支记录列表（见 2.3）中，与其他记录混合展示。

**触发**：用户在导入流程（见《02-资产汇总模块》）中确认导入，导入完成。

**处理规则**：

1. 记录生成：每条经用户确认导入的条目生成一条收支记录；其日期、方向、金额、分类、备注、所属账户的初始值按《02-资产汇总模块》的字段映射与分类映射结果带入（其中未能自动匹配分类的条目，在该导入流程中经用户批量指定后才导入，流程见 02）。
2. 来源标识：导入记录的数据来源标记为对应渠道（支付宝账单导入 / 微信账单导入 / 银行流水导入，取值口径见 01 第 5.3 节），生成后不可修改。
3. 进入统计：与手动记录规则完全一致——
   - 按记录日期归入每一个包含该日期的周期（周期归属规则见 4.3）；
   - 支出记录计入周期支出合计、对应分类已支出、预算进度、收支分类占比图；
   - 收入记录计入周期收入合计；
   - 转账类条目（如银行流水中的账户间划转）按 01 第 5.3 节不计入收支统计，仅在列表中可见。
4. 列表展示：与手动记录混合、按列表统一排序规则展示，每行展示来源标识。

**结果与状态变化**：导入完成后，周期统计总览（收入 / 支出合计）、预算进度、收支分类占比图立即包含导入的数据（与 01 场景 3 完成标志一致：当月收支分类占比图包含导入数据，可见支出金额排名前三的分类及各自金额）；若导入使某分类或总预算达到预警梯度，页面顶部提示条与预算卡片内高亮立即出现。

**字段定义**：与 2.1 字段定义一致，另有两点差异：数据来源为对应导入渠道（不可修改）；各字段初始值由 02 的映射规则确定而非用户手动填写。

**状态**：导入记录与手动记录无状态差异，保存（导入）后长期有效，可编辑、可删除。

**异常场景**：

| 场景 | 处理 |
|---|---|
| 导入记录的日期不在当前查看的周期内 | 正常生成；计入其日期所在的周期；用户切换周期或调整筛选后可见 |
| 导入记录的所属账户为空 | 允许；统计与预算不受影响（所属账户为选填，见 01 第 5.3 节） |
| 删除某条导入记录后，用户再次导入同一文件 | 是否判定为重复，遵循《02-资产汇总模块》的去重规则，本文不另行定义 |
| 导入条目被 02 的去重规则标记为疑似重复且用户选择跳过 | 该条目不生成收支记录，不进入任何统计 |

**银行流水文件导入的规则归属**：02 号文档已明确银行流水文件导入不在其 CSV 导入规则范围内（见《02-资产汇总模块》1.4 节），该导入的规则由本文档定义：其导入产物（收支记录）、进入统计与预算的口径、来源标识（「银行流水导入」，取值口径见 01 第 5.3 节）与上述支付宝/微信账单导入完全一致。因各银行导出流水的文件格式互不相同，其文件格式说明、字段映射、方向处理、去重与失败处理的具体规则，以及支持的银行与格式范围 [TBD]，须在实现前按目标银行的实际导出格式补充定义；其中"方向处理"遵循 01 第 5.3 节记账规则（账户间划转记为转账、不计入收支统计，见本节处理规则第 3 条）。

### 2.3 收支记录列表

**目的**：提供全部收支记录（手动 + 导入）的统一查看、筛选、编辑与删除入口，使用户能核对"这段时间钱进出多少、花在哪"。

**布局**：自上而下为筛选栏（周期、分类、方向三个筛选器 + 结果计数）、周期统计条（收入合计、支出合计、结余）、记录列表。每条记录展示：日期、方向标识（支出 / 收入 / 转账）、分类、备注（超长截断 [Assumption, TBD: 截断规则]）、金额（支出与收入以不同样式区分 [Assumption, TBD: 样式]）、所属账户（未填则不展示）、来源标识、「编辑」「删除」操作。

**触发**：用户进入本模块页面；或列表内数据因记一笔、导入、编辑、删除而发生变化。

**处理规则**：

1. 筛选：三个维度可任意组合，多条件之间为"同时满足"关系。

| 筛选器 | 可选值 | 默认值 |
|---|---|---|
| 周期 | 全部 / 各自然月（最近 [Assumption, TBD: 12] 个月）/ 各自定义周期 | 当前自然月 [Assumption, TBD] |
| 分类 | 全部 / 各一级分类（支出与收入两套分类并列可选）[Assumption, TBD: 二级分类是否作为独立筛选项] | 全部 |
| 方向 | 全部 / 支出 / 收入 / 转账 | 全部 |

2. 排序：按日期倒序；同一天内按保存时间倒序 [Assumption, TBD]。列表分批加载，每批条数 [TBD]。
3. 周期统计条：按当前所选周期计算三项——收入合计（周期内收入记录金额之和）、支出合计（周期内支出记录金额之和）、结余（收入合计减去支出合计的差额，可为负）；转账不计入任何一项。统计条只随「周期」筛选变化，不随分类、方向筛选变化 [Assumption, TBD]。
4. 编辑规则：点击「编辑」打开与记一笔一致的表单并预填该记录现有值（转账记录预填转出 / 转入账户）；来源标识不可编辑。保存后该记录按新字段值重新参与统计：改金额则各级合计与进度按新金额重算；改日期则周期归属随之变化（从原周期移出、计入新日期所在的周期）；改分类则预算归属随之变化（从原分类移出、计入新分类）；改方向则按新方向重新归类。
5. 删除规则：点击「删除」弹出确认对话框，明确提示"删除后无法恢复"（P0 不提供回收站或撤销 [Assumption]）；确认后记录从列表移除。
6. 删除已计入预算的记录后，预算进度回算规则：本模块中"已支出"始终是"周期内现存支出记录之和"的实时计算结果（见 4.1），不保留任何中间合计，因此删除即时生效，无需额外操作——所有包含该记录日期的周期，其支出合计、对应分类已支出、总预算与分类预算的进度、收支分类占比图、预警状态全部立即重算。例如：删除一笔 ¥50 的餐饮支出后，若该分类进度从 102% 降至 96%，预算卡片从「已超支」变为「接近超支」，顶部提示条文案同步更新；若降至 80% 以下，提示条自动消失（当日已手动关闭的情况见 5.6）。

**结果与状态变化**：筛选条件变化后列表与结果计数即时刷新；编辑或删除保存后，列表、周期统计条、预算进度、占比图、预警状态即时刷新。

**字段定义**：列表展示字段见「布局」；记录的完整字段定义见 2.1。

**状态**：列表有三种展示状态——

| 状态 | 触发条件 | 展示 |
|---|---|---|
| 正常展示 | 筛选结果非空 | 记录列表 |
| 筛选无结果 | 组合筛选下无匹配记录 | "没有符合筛选条件的记录" + 「清除筛选」入口 |
| 无任何记录 | 用户从未记过一笔也未导入过 | 初始空态：引导「去记一笔」或「导入账单」（导入入口见《02-资产汇总模块》） |

**异常场景**：除上述三种空态外——转账记录在"方向 = 支出"或"收入"筛选下不显示（转账与收支是不同方向）；被编辑改期的记录会从原筛选周期的列表中消失（因周期归属已变化），属正常行为。

5. **导入时的自动归类**：CSV 导入过程中账单条目到分类的自动匹配（映射规则）见《02-资产汇总模块》。

## 4. 双周期预算

预算是绑定在某个周期上的金额约束（见 01 第 5.5 节）——通俗地说，就是给一段时间的花费先定一个"最多花多少"的上限。预算周期支持月度与自定义两种形态、双维度并存（01 第 5.5 节）：月度按自然月自动滚动，自定义周期（典型如学期）由用户手动创建。同一时间可同时存在月度视图与一个或多个自定义周期视图，统计与预算进度分别查看、互不影响。预算只约束支出；收入记录不计入任何预算进度。

### 4.1 月度预算

**目的**：让用户按自然月设置并跟踪花费上限，覆盖"月初领生活费做预算"的核心场景（01 场景 1；解决 01 问题 P3）。

**布局**：月度视图下，总预算卡片内提供「设置预算 / 修改预算」入口；点击后打开预算编辑浮层 [Assumption, TBD: 形式]，内容为：总预算金额输入框 + 内置分类及自定义分类的预算金额列表（预置常用分类模板，见第 3 章清单）+「复制上月预算」按钮 +「保存」「取消」。保存后预算卡片区展示总预算卡片与各已设预算分类的卡片。

**触发**：用户在月度视图点击「设置预算」；或点击「修改预算」调整已有预算。

**处理规则**：

1. 设定口径：月度预算 = 总预算（该月支出总额上限）+ 分类预算（各一级分类的支出上限），均可只设置其一。预算金额为大于 0 的数字、两位小数、上限 [TBD]；输入 0 或负数不通过校验（0 视为未设置，见 6.2）。
2. 月度周期自动滚动（01 第 5.5 节）：进入新的自然月时，新月初始为「未设置预算」状态，不自动继承任何历史预算。
3. 从上月复制：
   - 「复制上月预算」按钮仅在上月存在已设置预算时可用，否则置灰并显示"上月无预算可复制"；
   - 复制内容为上月的总预算金额与上月各已设置分类的预算金额；上月已设置、但当前已被停用的分类被跳过，并提示跳过数量 [Assumption, TBD]；
   - 复制后进入待编辑状态，用户可修改任意金额，点击「保存」后才生效（与 01 场景 1"从上月预算一键复制后修改"一致）。
4. 分类预算合计与总预算的关系：允许不一致（例如只想用分类预算做细粒度控制）。当分类预算合计大于总预算时，保存时提示"分类预算合计已超过总预算"，但不阻止保存 [Assumption, TBD]。
5. 计算规则（预算进度的唯一口径）：
   - 已支出（总）= 该自然月内全部支出记录金额之和（不含收入与转账）；
   - 已支出（分类）= 该自然月内该一级分类（含其二级分类）的支出记录金额之和；
   - 进度 = 已支出 ÷ 预算金额；剩余可用 = 预算金额 − 已支出；超支金额 = 已支出 − 预算金额（可为负、为零）；
   - 百分比展示四舍五入取整 [Assumption, TBD]；
   - 上述数值始终按现存的收支记录实时计算，记录增删改或预算修改后即时重算，不保留中间结果。
6. 预算修改：总预算与分类预算金额可随时修改，保存后进度与预警状态立即按新金额重算（口径见 4.3）。

**结果与状态变化**：保存后，总预算卡片展示总预算、已支出、进度；各分类预算卡片展示对应数值；若在月初设置且当月尚无支出记录，进度均为 0%（与 01 场景 1 完成标志一致）。此后每笔支出记录计入对应分类的预算进度。

**字段定义**：

| 字段 | 必填 | 格式 / 约束 | 说明 |
|---|---|---|---|
| 预算周期 | —（自动） | 当前自然月 | 月度周期自动滚动，不可修改（01 第 5.5 节） |
| 总预算金额 | 设置预算时必填 | 大于 0，两位小数，上限 [TBD] | 该月支出总额上限 |
| 分类预算金额 | 否，可只设部分分类 | 同上 | 设置在一级分类上；二级支出并入一级计算 |

**状态**：未设置 / 已设置；已设置下按进度分为正常 / 接近超支 / 已超支（梯度判定见第 5 章）。

**异常场景**：

| 场景 | 处理 |
|---|---|
| 月中才首次设置预算 | 保存后进度立即按当月已支出计算，可能出现"保存即接近超支 / 已超支"，属正常行为，提示照常出现 |
| 只设总预算、不设分类预算 | 仅展示总预算进度条；分类卡片区显示"未设置分类预算"的引导 |
| 只设分类预算、不设总预算 | 分类进度正常展示；总预算卡片为「未设置」态，不展示进度条 |
| 分类预算合计超过总预算 | 保存时提示，不阻止 |
| 上月无预算 | 「复制上月预算」置灰 |

### 4.2 自定义周期（如学期）

**目的**：提供匹配大学生"学期"节奏的预算与统计区间，覆盖"学期初一次性到账、多周匀速消耗"的规划需求（01 问题 P3；01 第 5.5 节自定义周期）。

**布局**：周期切换器中提供「新建周期」入口；点击后打开创建表单（周期名称、开始日期、结束日期）。创建成功后，该周期作为新标签出现在周期切换器中；切入该周期视图后，统计总览、预算设置与展示、占比图、记录列表均与月度视图同构（仅周期边界不同）。

**触发**：用户点击「新建周期」创建；或切换到某个已有自定义周期查看。

**处理规则**：

1. 周期创建字段与校验：周期名称必填（自由文本，上限 [Assumption, TBD: 20 字]，允许与已有周期重名 [Assumption, TBD]）；开始日期、结束日期必填，结束日期不得早于开始日期（否则提示无法创建）。起止日期可任意落在过去或未来——允许用户在学期中段补建"本学期"周期（开始日期早于今天）。
2. 周期预算：创建后在该周期视图下设置总预算与分类预算，口径、复制来源与计算规则与 4.1 完全一致；"从上月复制"在自定义周期下不可用（上月概念仅存在于月度视图）[Assumption, TBD]。
3. 与月度视图的关系（并存、可切换、互不覆盖）：
   - 月度预算与各自定义周期预算相互独立，在任一视图下的设置与修改不影响其他视图；
   - 同一笔支出按其日期同时计入当月月度周期和每一个包含该日期的自定义周期，两边各自独立计算进度（01 第 5.5 节"区间重叠"规则）；
   - 自定义周期可与多个自然月重叠（如 9 月 1 日至次年 1 月 15 日的学期周期横跨 5 个自然月），统计聚合整个区间。
4. 周期状态：按"今天"与起止日期判定——未开始（开始日期在未来）/ 进行中（今天在区间内）/ 已结束（结束日期在过去）。各状态的行为差异见「状态」。
5. 周期修改：名称与起止日期可修改；起止日期修改保存后，该周期的统计与预算进度按新边界立即重算（记录按新区间重新归属）；预算金额修改同 4.1。
6. 周期删除：需确认对话框；删除该周期及其上的预算设置；不改动任何收支记录（01 第 5.5 节"周期是统计边界，记录不隶属、不存储于任何周期"）。删除当前正在查看的周期后，视图回到月度。
7. 同时存在的自定义周期数量上限 [TBD]（浏览器本地容量有限，见 01 第 4 章约束 3）。

**结果与状态变化**：创建成功后周期切换器出现新标签；该周期内已有日期的收支记录自动计入其统计（无需用户做任何归属操作）；设置预算后进度按区间内已支出立即计算。

**字段定义**：

| 字段 | 必填 | 格式 / 约束 | 说明 |
|---|---|---|---|
| 周期名称 | 是 | 自由文本，上限 [Assumption, TBD: 20 字] | 如"秋季学期" |
| 开始日期 | 是 | 日期 | 可为过去日期 |
| 结束日期 | 是 | 日期，不早于开始日期 | — |
| 总预算金额 | 否 | 同 4.1 | 创建后在周期视图下设置 |
| 分类预算金额 | 否 | 同 4.1 | 同上 |

**状态**：

| 周期状态 | 判定 | 行为 |
|---|---|---|
| 未开始 | 今天早于开始日期 | 统计与预算可设置、可查看（进度通常为 0%）；不产生预警提示 [Assumption, TBD] |
| 进行中 | 今天在起止区间内 | 完整功能：统计、预算、预警、占比图 |
| 已结束 | 今天晚于结束日期 | 统计与预算最终结果可查看，预算金额仍可修改（仅影响复盘展示数值）；不再产生页面顶部预警 [Assumption, TBD] |

**异常场景**：

| 场景 | 处理 |
|---|---|
| 结束日期早于开始日期 | 校验不通过，提示"结束日期不能早于开始日期"，无法创建 |
| 新建周期与已有周期区间重叠 | 允许（01 第 5.5 节），各周期独立统计 |
| 删除周期 | 确认后删除周期与预算设置；收支记录全部保留、不受影响 |
| 学期周期横跨多个月 | 正常：区间内所有月份的记录聚合统计；与各月月度视图并行不悖 |

### 4.3 周期边界处理

**跨周期记录归属**：一律按记录日期判定——一条收支记录被计入每一个"包含其日期"的周期，各周期独立统计（01 第 5.5 节）。例如一笔 9 月 15 日的餐饮支出，计入 9 月月度周期，也计入区间为 9 月 1 日至次年 1 月 15 日的"秋季学期"周期；若还存在另一个包含 9 月 15 日的自定义周期，则同样计入。记录被编辑改期后，归属随之按新日期重新判定。记录本身不隶属、不存储于任何周期，因此删除或修改周期不改动任何记录。

**周期未设预算时的展示**：该周期视图的预算卡片区显示"本周期未设置预算"文案与「设置预算」入口；不展示任何进度条；不产生任何预警。收入合计、支出合计、结余与收支分类占比图正常展示——统计不依赖预算。

**预算中途修改的处理口径**：预算金额（总预算或分类预算）被修改并保存后，进度与预警状态立即按新金额重算，无需其他操作；上调预算可能使预警立即消失，下调可能使预警立即出现，均属正常。本产品不保留预算修改历史（无"预算修改记录"功能，P0 不做 [Assumption]）。自定义周期的起止日期被修改后，统计边界变化，进度同样立即重算。已结束周期的预算修改仅影响复盘展示数值，不触发预警提示。

## 5. 超支预警

### 5.1 目的

在用户的某项预算接近或超出上限时，通过页面内提示使用户无需主动计算即可察觉，从而调整后续花费。提示方式为页面顶部提示条 + 预算卡片内高亮（已确认产品决策）；**不做浏览器推送通知**——所有提示仅在用户打开页面时可见（见 5.7）。

### 5.2 布局与触发

提示条展示在页面顶部（页面内容之上）；卡片高亮发生在对应的预算卡片内。预警状态的评估时机为：打开或刷新本模块页面时、保存 / 编辑 / 删除收支记录后、CSV 导入完成后、修改预算金额或预警阈值后、切换周期视图时。评估对象为**当前查看的周期视图**内已设置预算的总预算与各分类预算 [Assumption, TBD: 仅对当前视图周期产生提示，不跨视图提醒]；预警仅对处于"进行中"的周期生效（见 4.2 状态表）。

### 5.3 梯度规则

预警分两级梯度，判定对象（总预算、每个已设预算的分类）各自独立判定，可同时处于不同梯度：

| 梯度 | 触发条件 | 页面顶部提示条 | 预算卡片内高亮 |
|---|---|---|---|
| 接近超支 | 进度 ≥ 阈值且 < 100% | 展示提示条（接近超支样式 [样式 TBD]） | 进度条变为警示色（如黄色 [色值 TBD]），展示剩余可用金额 |
| 已超支 | 进度 ≥ 100% | 展示提示条（超支样式 [样式 TBD]） | 进度条变为超支色（如红色 [色值 TBD]），展示超支金额与"已超支"标注 |

- 接近超支的默认阈值为 80% [Assumption, TBD]，用户可在设置中自定义调整（可调范围以 05 号文档预算规则的定义为准 [Assumption, TBD]）；调整保存后所有预警状态立即按新阈值重算。
- 已超支阈值固定为 100%，不可调整。

### 5.4 页面顶部提示条文案

| 判定对象 | 梯度 | 文案模板 |
|---|---|---|
| 分类预算 | 接近超支 | 「{分类名}」{周期称呼}预算已使用 {N}%，剩余 ¥{剩余金额} |
| 分类预算 | 已超支 | 「{分类名}」{周期称呼}预算已超支 ¥{超支金额} |
| 总预算 | 接近超支 | {周期称呼}总预算已使用 {N}%，剩余 ¥{剩余金额} |
| 总预算 | 已超支 | {周期称呼}总预算已超支 ¥{超支金额} |

周期称呼：月度视图为"本月"；自定义周期为该周期名称（如"秋季学期"）。多条提示同时满足时的展示规则：按"已超支优先于接近超支、总预算优先于分类预算"排序 [Assumption, TBD]，最多同时展示 [Assumption, TBD: 3] 条，其余折叠为"+N"入口，点击后展开完整列表。

### 5.5 预算卡片内高亮

高亮始终实时反映当前进度所处梯度（正常 / 接近超支 / 已超支），不受提示条"手动关闭"影响（关闭提示条只隐藏顶部提示，卡片高亮保留）。高亮的具体样式（颜色、闪烁与否）[TBD]。

### 5.6 提示消失与恢复规则

1. **手动关闭**：提示条右侧提供关闭按钮；点击后该条提示当天（自然日）内不再展示；次日若触发条件仍满足，则恢复展示。
2. **梯度升级**：当日已手动关闭的"接近超支"提示，若该对象升级为"已超支"，立即重新展示（升级视为一条新提示，不受当日关闭限制）。
3. **条件消失**：当进度回落到阈值以下（因删除记录、编辑记录、导入跳过、上调预算等），提示条自动消失，无需手动关闭；卡片高亮同步恢复常规样式。
4. 预算卡片内高亮无"关闭"概念，始终与当前进度一致。

### 5.7 明确不做的事

不做浏览器推送通知（已确认产品决策）：产品不发送浏览器通知、弹窗提醒、短信、邮件等任何页面外的提醒；所有超支信息只在用户主动打开页面时以页面内提示条与卡片高亮的形式呈现。

### 5.8 状态与异常场景

提示条的单条状态：展示中 / 当日已关闭 / 条件消失（不再展示）。

| 场景 | 处理 |
|---|---|
| 当前周期所有预算均未设置 | 无任何提示 |
| 分类预算仅设 ¥1 且已花 ¥1 | 立即判定已超支，正常展示提示与高亮 |
| 用户调整接近超支阈值 | 保存后立即按新阈值重算全部预警状态，提示条与高亮即时增减 |
| 已结束的周期 | 不再产生顶部预警提示；复盘视图中的进度条仍按历史梯度着色 [Assumption, TBD] |
| 当日关闭后又删除了一笔大额支出使进度跌破阈值 | 提示本就不会再展示（条件已消失）；次日也不会恢复 |

## 6. 可视化数据口径

本模块涉及三类图表中的两类：收支分类占比图与预算进度条（另一类资产趋势图属《02-资产汇总模块》）。两类图表均随所选周期视图联动。

### 6.1 收支分类占比图

**目的**：展示所选周期内支出在各分类上的构成（某分类占比即其支出占总支出的大约比例），回答"钱花在哪了"（对应 01 场景 3 完成标志：可见支出金额排名前三的分类及各自金额）。

**布局**：周期视图统计区，由占比图（环形图 [Assumption, TBD: 图形形态]）与分类金额排行列表（按金额降序、前三名突出展示 [Assumption, TBD: 突出方式]）组成。

**触发**：进入页面、切换周期、记录增删改、导入完成。

**处理规则**：

1. 统计范围：所选周期内日期的全部**支出**记录；收入与转账不计入。提供"支出 / 收入"维度切换，切换后按收入分类统计收入构成 [Assumption, TBD]。
2. 聚合维度：一级分类（记到二级分类的金额并入其一级分类，见 3.3）。
3. 占比 = 该一级分类支出 ÷ 周期总支出，展示百分比与金额；金额为零的分类不出现在图中。
4. 周期边界：记录日期落在所选周期区间内即计入；自定义周期跨多月时聚合整个区间，不按月拆分。
5. 空数据处理：周期内无支出记录时，不绘制图形，展示占位文案"本周期还没有支出记录"，并附「去记一笔」与「导入账单」（导入入口见《02-资产汇总模块》）两个引导入口。

**结果与状态变化**：数据变化后图与排行即时刷新，无需手动刷新页面。

**异常场景**：周期内仅有一笔支出（单分类占比 100%，正常展示）；周期内只有收入记录（支出维度为空态，同空数据处理；切换到收入维度可看收入构成）。

### 6.2 预算进度条

**目的**：以进度条形式直观展示预算消耗程度（进度 = 已支出 ÷ 预算，即"已经花掉的钱占预算上限的比例"），是预警高亮的载体。

**布局**：总预算卡片内 1 条；每个已设预算的分类卡片内各 1 条。

**触发**：进入页面、切换周期、记录增删改、导入完成、预算修改。

**处理规则**：

1. 口径：进度 = 已支出 ÷ 预算金额（与 4.1 计算规则一致，实时聚合）。
2. 展示元素：进度条、百分比、已支出金额、预算金额、剩余可用金额（或超支时的超支金额）。
3. 颜色梯度：与第 5 章预警梯度一致——正常（常规色）/ 接近超支（警示色）/ 已超支（超支色）。
4. 超支后的展示方式：进度条封顶满格展示（不按超过 100% 的真实比例拉伸 [Assumption, TBD]），在进度条旁以文字标注"已超支 ¥{超支金额}"与超支色提示。
5. 分类预算未设置的分类：不展示该分类进度条，仅展示已支出金额与「设置预算」入口。

**结果与状态变化**：进度随记录与预算变化即时重算刷新；梯度切换（正常 ↔ 接近超支 ↔ 已超支）时颜色即时切换。

**异常场景**：

| 场景 | 处理 |
|---|---|
| 预算未设置 | 不展示进度条；卡片显示"未设置预算"与「设置预算」入口 |
| 预算金额为 0 | 等同未设置处理 [Assumption, TBD] |
| 月初已设预算、尚无支出 | 进度 0%，剩余可用 = 预算金额 |
| 预算已设、已支出为 0 | 进度 0% |
| 已结束周期 | 进度条按最终数据展示，颜色按历史梯度着色，不产生新的顶部提示 [Assumption, TBD] |

## 2. 无账号本地存储方案

### 2.1 存储模型（权威定义）

**定义**：本应用无账号体系。用户打开网页即可使用，不需要注册、登录或提供任何身份信息；使用过程中产生的全部数据，保存于用户当前使用的浏览器为本应用保留的本地空间中，与任何外部服务无关。

三个可观察的推论：

1. 同一浏览器（同一设备）下次打开应用时，数据仍然在——这是"本地存储"给用户的直接体验。
2. 换一个浏览器、换一台设备打开，看到的是空的首次使用状态——本地数据不跟随人走（后果见 2.4）。
3. 应用内不存在"退出登录""切换账号"一类操作，也不存在"别人看不到我的数据"的账号隔离——凡能使用该设备该浏览器的人，都能看到本应用中的数据（对应的安全建议见第 4.2 节）。

**不存储的内容**（与清单同等效力）：本应用无账号体系，因此不存在密码；产品不收集姓名、手机号、身份证号等任何身份信息，不要求填写支付宝/微信/银行的账号、密码或验证码；账户备注、目标备注等为用户自由填写文本，产品无法禁止用户在其中填写敏感信息，因此在使用说明中给出"请勿在备注中填写密码、证件号等敏感信息"的如实建议（见 4.2）。产品不接入任何用户行为统计类外部服务 [Assumption, TBD：若后续引入任何第三方服务，本条与隐私说明页必须先如实更新再上线]。

### 2.3 容量边界

**产品可感知表述（权威表述，界面文案以此为准）**：浏览器本地存储的容量是有限的。以记账场景的典型数据量（数年间的账户、快照、每月导入的账单）使用，通常不会触及上限；但数年高频使用、特别是长期大量导入大时间跨度的账单文件，可能逐渐接近上限。不同浏览器对本地存储的实现不同，实际容量表现存在差异 [TBD]。

与 [01](01-产品定位与整体方案.md) 约束 3 的口径一致：产品**不承诺无限期保留全部导入的账单明细**，容量对应的数据保留策略 [TBD]。在该策略确定之前，产品的固定行为是：**绝不自动删除任何用户数据来腾出空间**（见 1.3 负面清单）。

**容量不足时的可观察行为**（本节为容量异常处理的权威定义处，[02](02-资产汇总模块.md)、[05](05-自定义设置模块.md) 引用此处）：

| 场景 | 产品行为 |
|---|---|
| 保存操作因空间不足而失败 | 页面提示"本地存储空间不足，本次保存未完成"；已保存的历史数据不受本次失败影响 |
| 提示中必须给出的处理建议 | ① 导出备份文件（第 3.1 节）；② 删除不再需要的历史数据（收支记录、旧快照等删除入口见各模块文档）；③ 清空全部数据（第 2.5 节，须先备份） |
| 是否提供"已用容量"的可感知展示 | [TBD] |
| 分类、账户等各类型的数量上限 | 各类型是否设上限及上限值随容量策略一并确定 [TBD]；达到上限时的提示行为以本节表格为准 |

### 2.4 数据清除行为与丢失风险（权威定义）

本地数据受浏览器自身机制管理，下列后果是浏览器环境的产品性事实，本应用无法阻止、无法提前预警、无法代为恢复。**前置告知义务**：首次使用告知流程（第 7 章）必须在使用开始前向用户告知本节后果，隐私说明页（4.3 节）常备本节内容。

| 场景 | 后果 | 产品行为 |
|---|---|---|
| 清除浏览器数据（清除本站数据或全部数据） | 本应用全部本地数据被一并删除，无法找回；若有备份文件，可按第 3.2 节恢复 | 无法阻止；唯一补救是备份导入 |
| 换浏览器使用 | 数据不跟随：同一设备的不同浏览器之间互不相通 | 告知后迁移路径：旧环境导出备份 → 新环境导入 |
| 换设备使用 | 数据不跟随：新旧设备之间无任何同步通道（01 约束 3，不做云同步） | 同上 |
| 长期不使用 | 部分浏览器会自动清理长期未访问网站的本地数据 [触发条件随浏览器而异，TBD] | 在隐私说明页告知该风险，建议定期打开使用并保持备份 |
| 无痕/隐私模式使用 | 关闭无痕窗口后，期间录入的全部数据随之消失，无法保留 | 产品不依赖运行时检测，在首次使用告知与隐私说明页中说明该限制 [是否提供无痕模式检测提示 TBD] |

### 2.5 功能：清空全部数据

**目的**：让用户在已持有备份的前提下，主动将应用恢复到首次使用状态（如数据混乱想从头再来、设备转交他人）。[05](05-自定义设置模块.md) 已将此功能从"恢复默认"中排除并指派到本文档。

**触发**：设置页"数据管理"区 →"清空全部数据"入口。

**处理规则**：

| 步骤 | 规则 |
|---|---|
| 1. 首次确认 | 弹窗明示范围："将删除本应用在你浏览器中的全部数据（第 2.2 节清单 S1～S9，二期上线后含 S10 自选股），删除后无法恢复"；提供"取消"与"继续" |
| 2. 备份快捷路径 | 同一弹窗内提供"先导出备份再清空"快捷按钮；点击后先执行第 3.1 节导出流程，完成后回到确认弹窗 [Assumption, TBD：是否强制先备份后再允许清空为推断性决策，当前方案为引导而非强制，理由是强制会增加一个不可绕过的前置步骤，与产品轻量精神不符] |
| 3. 执行 | 再次确认后执行删除 |

**结果与状态变化**：全部本地数据被移除；应用回到 [01](01-产品定位与整体方案.md) 场景 6 的初始形态（占位引导状态）；首次使用告知的确认状态随之清除，下次打开应用时告知层再次出现（见第 7 章）。

## 3. 数据导出与导入备份机制

备份是本地存储方案下唯一的数据保全与迁移手段（[01](01-产品定位与整体方案.md) 约束 3："导出备份文件是唯一补救手段，且备份责任在用户"）。本章定义三个功能：导出、导入恢复、备份提醒。三者入口均位于设置页"数据管理"区（页面组织以 [05](05-自定义设置模块.md) 为准，功能行为以本文档为准）。

### 3.1 功能：导出备份文件

**目的**：把用户在本应用中的全部数据（第 2.2 节清单全部条目）一次性生成为一个可自行保管的备份文件，作为数据丢失前的补救手段（2.4 节各场景）与设备/浏览器迁移的载体。

**触发**：

| 入口 | 说明 |
|---|---|
| 设置页 → 数据管理 →"导出备份文件" | 常驻主入口 |
| 首次使用告知层内的入口说明 | 告知层内说明导出入口的位置（首次使用时通常尚无数据可导，故只告知位置，不放置立即导出按钮）；对应 [01](01-产品定位与整体方案.md) 场景 6"首次展示备份文件导出入口" |
| 容量不足提示、清空确认弹窗、备份提醒条 | 各自提供跳转导出的快捷路径 |

**处理规则**：

| 规则 | 内容 |
|---|---|
| 导出范围 | 全量用户数据：第 2.2 节清单 S1～S9 全部（含应用状态记录，使恢复后各声明确认状态不丢失）；自选股（S10）在二期上线后纳入同一备份文件。不支持按类型选择部分导出 [Assumption, TBD：理由是备份的唯一目的是"完整恢复"，部分导出容易制造"以为备份了其实没备全"的错觉，故 P0 只提供全量] |
| 导出形态 | 单一备份文件，由用户选择保存位置（本机、U 盘、个人网盘等由用户自行决定）。文件的内部组织方式为实现细节，本文档不规定；对用户的形态承诺是：可在本应用中再次导入并完整恢复 |
| 导出时机 | 全程在用户本地完成，不经过任何网络传输（与第 4.1 节"数据不出本地"一致） |
| 命名建议规则 | 默认文件名形如"校园理财管家-备份-20261030"（产品名 + 日期）；同一日多次导出时在末尾追加序号（-1、-2）避免相互覆盖 [Assumption, TBD：命名规则为推断性设计，评审可调整] |
| 导出完成提示 | 提示语明确告知："备份文件包含你的全部数据，请妥善保管；若存放在网盘或发给他人，等于交出你的全部财务记录" |

**结果与状态变化**：用户获得一个备份文件；应用记录"最近一次备份导出时间"（第 3.3 节提醒的计时基准）；不发生任何其他数据变化。

### 3.2 功能：从备份文件恢复数据

**目的**：在数据丢失后（2.4 节场景）或新环境迁移时，把此前导出的备份文件恢复为应用的当前数据。

**触发**：设置页 → 数据管理 →"导入备份文件"。

**处理规则**（流程）：

| 步骤 | 规则 |
|---|---|
| 1. 选择文件 | 用户选择一个备份文件；仅接受本应用导出的备份文件，无法识别时提示"这不是本应用导出的备份文件，无法导入"，不发生任何数据变化 |
| 2. 预览确认 | 读取文件并展示概况供核对：备份生成日期、账户数、收支记录条数、储蓄目标数等计数信息 |
| 3. 冲突判定与处理 | 按下方"冲突处理口径"执行 |
| 4. 执行与完成提示 | 恢复完成后提示概况（恢复的账户数、记录条数），页面数据即时刷新 |

**冲突处理口径（导入到已有数据环境）**——权威方案：**询问后覆盖，不提供合并**。

| 本地数据状态 | 处理 |
|---|---|
| 本地为空（首次使用或刚清空） | 直接恢复，无需选择；完成后进入恢复后的数据状态 |
| 本地已有数据 | 弹出冲突处理选择，仅提供两个选项：**"覆盖"**（本地当前全部数据被备份文件内容替换，替换后无法撤销）与**"取消"**（不做任何改动）；确认弹窗内同时提供"先导出当前数据再覆盖"的快捷路径（执行第 3.1 节导出后回到确认），保证覆盖前的本地数据可留底 |

不提供"合并"的理由 [Assumption, TBD]：① 合并需对清单 S1～S9 每类数据分别定义重复判定与取舍规则，复杂度高且一旦合并出错不可逆，与个人小应用的维护资源不匹配（01 约束 3）；② "先导出当前数据再覆盖"的快捷路径使覆盖操作双向可回退，误操作风险已有兜底；③ 账单类记录在极端情形下可通过 CSV 重新导入补回（[02](02-资产汇总模块.md) 第 4 章），原数据存在第三重找回途径。若上线后用户对合并诉求强烈，可重新评估本决策。

**结果与状态变化**：恢复成功后，应用内全部数据以备份文件内容为准；首次使用告知与各模块声明确认状态一并按备份文件恢复（备份中的确认状态为"已确认"时，恢复后不重复弹出首次告知层）。

### 3.3 功能：定期备份提醒

**目的**：把"备份责任在用户"（01 约束 3）转化为产品辅助：在用户长期未备份且期间有新数据产生时主动提醒，降低数据丢失风险的积累。

**触发**：距最近一次成功导出备份的天数超过提醒周期，且期间本地发生过任何数据写入（记账、快照、导入等），则在用户下次打开应用时触发。

**处理规则**：

| 规则 | 内容 |
|---|---|
| 是否提供 | 提供定期备份提醒 [Assumption, TBD：是否提供为推断性决策，理由见下] |
| 默认状态与周期 | 默认开启，周期为 30 天 [Assumption, TBD：30 天约等于一个生活费周期，与主画像"以周/月为单位使用"的节奏匹配；默认开启而非关闭的理由是主画像用户备份意识弱、且这是"首次明确告知"义务的延伸。默认值与周期可经评审与试用数据调整] |
| 提醒形态 | 页面顶部非阻断提示条："已超过 N 天未备份，建议导出备份文件"，附"立即导出"与"关闭本次提醒"两个操作 |
| 用户控制 | 设置页可关闭提醒功能整体开关、调整周期；关闭后不再出现 |

**结果与状态变化**：用户导出成功后计时基准重置；点"关闭本次提醒"仅消除当次提示条，不改变开关状态，下个周期到达后再次提醒。

## 4. 隐私保护说明

### 4.1 "数据不出本地"的权威定义

**定义**：用户在本应用中录入、导入、产生的全部数据（第 2.2 节清单），仅保存于用户当前使用的浏览器本地。本产品不将这些数据上传至任何服务器，不将其用于任何分析或共享，不向任何第三方提供。

该定义的可观察含义：

| 承诺 | 可观察含义 |
|---|---|
| 不上传至任何服务器 | 应用内没有任何"同步""上传"操作；唯一离开浏览器的数据形态，是用户主动导出并自行保存/发送的备份文件（第 3.1 节），该行为由用户自主决定，产品不代为执行 |
| 不用于任何分析 | 产品不接入任何用户行为统计类外部服务（2.2 节"不存储的内容"）；无后端即无分析发生的环境 |
| 不向任何第三方提供 | 产品无数据外发通道；不存在"分享给好友""生成公开链接"类功能 |

### 4.2 边界（如实说明，不夸大）

"数据不出本地"不等于"数据绝对安全"。以下边界如实写清，隐私说明页与首次使用告知必须包含：

| 边界 | 如实说明 | 产品给出的建议 |
|---|---|---|
| 本地 ≠ 绝对安全 | 凡能使用该设备该浏览器的人，打开本应用即可看到全部数据；本应用无账号、无密码保护，无法对设备层面的安全负责 | 为设备设置锁屏密码；不在共用设备上录入财务数据；离开设备前关闭页面 |
| 备份文件本身含全部数据 | 备份文件包含用户全部财务记录，谁拿到备份文件谁就能看到 | 备份文件存放在仅自己可控的位置；不随意发送给他人；转存网盘时自行确认网盘账号安全 |
| 备注等自由文本不受产品控制 | 产品无法禁止用户在备注中填写敏感信息 | 请勿在备注、目标名称等文本中填写密码、证件号等敏感信息 |
| 网页应用的网络交互 | 打开本应用本身需要联网加载页面文件；这类交互获取的是应用运行所需的内容，方向是"向你的设备提供应用"，不涉及用户数据的发送 | 无需处理，如实知晓即可 |
| 二期行情数据的方向界定 | 二期股票行情（[06](06-股票分析模块.md)）为"从外部数据源获取行情信息展示给你"，不属于"上传用户数据"；但行情获取过程中是否伴随向数据源发送任何与用户有关的信息 [TBD，以 [06](06-股票分析模块.md) 第 5 章数据源调研结论为准] | 二期上线行情功能时，隐私说明页须同步更新外部交互说明（见 4.3 更新义务） |

**判断标准（权威界定）**：一项网络交互是否属于"数据上传"，以**用户数据是否离开用户设备**为唯一判据。据此，页面加载与行情获取（下行获取外部信息）不属于数据上传；用户主动导出备份文件后自行上传该文件，属于用户自主行为，不在本产品承诺范围内。

### 4.3 隐私说明页（内容要求与入口）

**目的**：把 4.1、4.2 的定义与边界完整、常备地呈现给用户，作为隐私承诺的唯一书面处。

**内容要求**（隐私说明页必须包含的清单）：

| 编号 | 内容模块 | 对应章节 |

## 7. 首次使用告知流程

**目的**：在用户开始使用前，一次性、明确地告知本地存储方案的四个关键事实，履行 [01](01-产品定位与整体方案.md) 约束 3 的"首次使用时明确告知"义务（对应 [01](01-产品定位与整体方案.md) 1.4 节预期结果 7：页面明确告知数据存储于浏览器本地、支持导出备份文件、不支持多端云同步）。

**触发**：用户首次打开应用——本地不存在首次使用告知的确认状态记录（清单 S9）时，在进入初始化引导（[01](01-产品定位与整体方案.md) 场景 6）之前展示告知层。清空全部数据（2.5 节）后，确认状态清除，下次打开重现告知层；从备份文件恢复（3.2 节）不重现（确认状态随备份恢复）。

**告知事项清单**（告知层必须包含的事项与语义方向）：

| 编号 | 告知事项 | 必须出现的语义 |
|---|---|---|
| 1 | 数据存储方式 | 你的全部数据保存在当前浏览器的本地空间，不上传服务器（定义见 4.1，浅白表述） |
| 2 | 无云同步与丢失风险 | 不支持多端云同步；清除浏览器数据、换浏览器、换设备会导致数据丢失且无法找回（2.4 节后果） |
| 3 | 备份建议 | 建议定期导出备份文件；导出入口位于设置页"数据管理"区；备份文件请妥善保管 |
| 4 | 教育性定位 | 本应用全部投资相关内容为教育性信息，不构成投资建议（6.1 要点版） |
| 5 | 不接触真实资金 | 本应用不提供支付、不代扣代缴、不代你操作资金（5.2 负面清单的浅白表述） |
| 附 | 完整说明入口 | "查看完整隐私说明"链接（打开隐私说明页，见 4.3） |

**确认交互规则**：

| 规则 | 内容 |
|---|---|
| 确认动作 | 告知层底部为"我已知晓，开始使用"按钮，单击即完成确认并进入初始化引导（[01](01-产品定位与整体方案.md) 场景 6，每一步可跳过） |
| 不强制逐条阅读 | 不设停留时长、不设逐项勾选 [Assumption, TBD：单击确认为推断性交互决策，理由是履行告知义务的可观察标准是"展示行为发生且提供完整说明入口"，而非强制阅读；与"引导可跳过"的产品精神一致；评审可改为逐项确认] |
| 查看完整说明 ≠ 确认 | 告知层内打开隐私说明页不消除告知层；确认只能通过单击按钮发生 |
| 确认状态 | 记录一次（清单 S9），此后不再弹出；无痕模式中因数据不保留（2.4 节），每次打开都会再次见到告知层——该现象本身即无痕限制的实证，不作为异常处理 |
| 与初始化引导的顺序 | 告知层在前、引导在后；即使用户引导全部跳过，告知确认已发生 |

**结果与状态变化**：确认后，应用进入首次使用状态（[01](01-产品定位与整体方案.md) 场景 6 的初始形态）；确认状态写入本地；后续各投资相关模块的首次进入提示（6.3 节）按各自文档独立触发，不受本章影响。

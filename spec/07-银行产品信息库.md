## 1. 模块定位与信息来源声明（本章为权威声明）

### 1.1 模块定位

本模块是面向理财小白的银行个人金融投资产品公开信息聚合与科普模块，向用户提供三项能力，仅此三项：

| 能力 | 内容 | 详见 |
|---|---|---|
| 类型化信息浏览 | 按"银行 × 产品类型"二维关系组织的银行在售产品类型信息框架 | 第 2 章 |
| 字段化信息展示 | 每条产品信息以统一字段结构展示，未核实数值一律标 [TBD] | 第 3 章 |
| 小白向概念解释 | 存款保险制度、风险等级、业绩比较基准等概念的浅白解释 | 第 5 章 |

依据 [01](01-产品定位与整体方案.md) 第 6.1 节模块架构，本模块属于信息消费型扩展，不被任何 P0 模块依赖；缺少本模块不影响"记录—统计—规划"的 P0 闭环成立。

### 1.2 信息来源与整理方式（权威声明）

| 项目 | 声明内容 |
|---|---|
| 信息来源 | 银行官网、银行官方 App 的公示信息等公开渠道；不使用任何非公开或无法核实来源的信息 |
| 整理方式 | 人工整理；每条信息标注信息来源与信息更新日期（与 [01](01-产品定位与整体方案.md) 约束 4 的要求一致） |
| 时效性 | 人工整理存在时滞：银行公示变更后，本模块信息只有在人工复核后才更新，可能滞后于银行最新公示；信息与银行官方不一致时，一律以银行官方信息为准 |
| 数值规则 | 未能核实的数值（利率、费率、起购金额等）一律标记 [TBD]，不虚构、不估算、不引用无法溯源的数值 |

### 1.3 边界声明（不可逾越）

以下三条为模块级硬边界，效力等同于 [01](01-产品定位与整体方案.md) 第 4 章第一性原理约束，任何二期设计不得突破：

| 编号 | 边界 | 可观察的含义 |
|---|---|---|
| B1 | 不自动查询用户持仓 | 不提供任何查询用户银行账户余额、持仓、交易记录的功能或入口（依据 [01](01-产品定位与整体方案.md) 约束 1：微信理财通、支付宝、各大银行均不向个人第三方应用开放资产查询能力，本模块不例外） |
| B2 | 不构成投资建议 | 不推荐任何具体产品，不做收益排行、收益对比引导，不输出"买哪个"类结论（依据 [01](01-产品定位与整体方案.md) 约束 4） |
| B3 | 不代销、不提供购买跳转 | 不提供任何购买入口、代销页面或第三方购买渠道的跳转链接 |

#### 1.3.1 官网链接的推断性决策

[Assumption, TBD] 本模块默认**不提供**银行官网或产品页链接，理由：

1. 链接到具体产品页面可能构成导购与推荐暗示，与边界 B2、B3 冲突；
2. 银行页面链接易失效，人工维护成本高，失效链接反而误导用户；
3. 收录银行的名称为公开信息，用户可自行检索银行官网核实。

若评审认为提供链接有助于用户自行核实信息，则仅考虑"银行官网首页链接"层级、不链接具体产品页 [最终决策 TBD]。

### 1.4 与用户数据的隔离

本模块为只读内容模块，与用户数据完全隔离，具体表现为：

- 不读取、不写入、不关联用户的账户、资产快照、收支记录、分类、预算周期、储蓄目标等任何本地数据；
- 页面不出现任何基于用户数据的个性化内容（无"为你推荐""根据你的持仓"形态）；
- 用户在本模块内的一切浏览行为不产生任何记录。

上述表现与产品本地优先的整体形态一致（见 [01](01-产品定位与整体方案.md) 约束 3）。

### 1.5 二期优先级说明

- MVP（P0）不包含本模块，本模块为 P1（二期），与 [01](01-产品定位与整体方案.md) 第 6.3 节分期边界一致；分期理由（依赖方向、数据获取成本、合规成本、验证顺序）见该章，本文档不重复。
- 收录银行清单、产品条目数量等以人工整理的可行性为准，P1 阶段先以精选少量类型与条目起步（[01](01-产品定位与整体方案.md) 约束 4：先以精选少量产品起步 [数量 TBD]）；模块最终范围 [P1 最终范围裁量 TBD，见 [01](01-产品定位与整体方案.md) 第 6.3 节]。
- 本文档为二期规划输入，不构成任何实现节奏承诺。

## 2. 信息聚合框架（银行 × 产品类型）

### 2.1 功能目的

给出本模块信息组织的核心结构：全部产品信息按"银行 × 产品类型"的二维关系组织，让小白用户先看懂产品类型，再查看不同银行在该类型下的条目，建立"银行在售产品有哪些类型、各类是什么"的认知框架。

### 2.2 展示结构与选择理由

**候选结构**：（a）"行 = 银行、列 = 产品类型"的矩阵表；（b）以产品类型为主线的分类浏览 + 银行筛选。

**选定结构**：（b）以产品类型为主线分类浏览 + 银行筛选。具体形态：

- 模块落地页为产品类型分类页：展示类型卡片列表，每张卡片含类型名称、一句小白向解释（见 2.4）、典型风险档标注；
- 点击类型卡片进入该类型的信息列表页：列表页顶部提供银行筛选（单选 / 多选 / 全部 [筛选交互细节 TBD]）；
- 列表条目默认按发行银行分组展示或按期限结构组织 [默认组织方式 TBD]；不提供按利率 / 业绩比较基准数值排序的功能（原因见 5.4 负面清单）。

**选择理由**（相对矩阵表）：

1. **认知路径匹配**：小白的典型问题是"定期存款是什么、大额存单和理财有什么区别"（先类型、后银行），而非"比较哪家银行"（先银行、后类型）；矩阵把银行放在主位，与目标用户的认知顺序相反（[01](01-产品定位与整体方案.md) 第 2.1 节主画像："对概念不清楚或仅模糊听说"）。
2. **字段结构差异**：存款类条目以"利率 + 期限 + 起购金额"为主，理财类条目以"风险等级 + 业绩比较基准 + 期限"为主（见第 3 章）；矩阵的单元格无法承载两类不同的字段结构，分类页可以为每类定义专属字段结构。
3. **规避收益对比引导**：矩阵形态天然诱导用户横向比较同一列中各银行的数值（即跨银行利率对比），与"不做收益对比引导"的负面清单（5.4）冲突；分类 + 筛选结构默认按类型与期限组织，弱化数值横比。
4. **可读性**：银行数量或类型数量任一增长，矩阵的行列数即增长、单格信息被压缩；分类结构在同样信息量下浏览层级不变。

二维关系不丢失：类型列表页内每条条目均携带"发行银行"字段，并支持按银行筛选——"银行"维度以筛选方式保留，两种候选结构承载同一份二维信息。

**布局**：模块落地页从上至下依次为：合规声明条（第 6 章）、时效性声明条（第 4 章）、产品类型卡片列表。

**触发**：用户从主导航进入本模块（落地页）；在落地页点击某类型卡片（进入该类型列表页）。

**处理规则**：

| 场景 | 规则 |
|---|---|
| 进入模块落地页 | 展示合规声明条、时效性声明条与类型卡片列表；每个类型名称首次出现处附一句浅白解释（遵循 [01](01-产品定位与整体方案.md) 约束 5） |
| 在类型列表页选择银行筛选 | 列表仅展示所选银行的条目；可随时清除筛选恢复全部 |
| 切换至另一类型列表页 | 银行筛选条件恢复默认（全部银行）[Assumption, TBD：是否跨页面记忆筛选条件] |

**结果与状态变化**：筛选操作只改变当前列表的可见条目集合，不改变任何条目内容；用户的浏览与筛选行为不产生任何持久记录（见 1.4）。

**异常场景**：

| 异常场景 | 产品行为 |
|---|---|
| 筛选结果为空 | 展示"该银行在本类型暂无收录条目"占位提示，并提供清除筛选的入口 [占位文案 TBD] |
| 某银行 × 某类型组合无条目 | 该组合不出现在筛选结果中；不虚构占位条目 |
| 某类型列表整体为空 | 展示"本类型信息整理中"占位（说明本模块信息为人工整理、逐步收录，见 1.2） |

## 3. 展示字段定义

### 3.1 产品信息条目字段

每条产品信息条目包含且仅包含以下字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 产品类型 | 是 | 归属 2.4 类型清单之一 |
| 发行银行 | 是 | 按 2.3 银行条目标注 |
| 风险等级 | 理财类必填 | 按 [01](01-产品定位与整体方案.md) 第 5.7 章五级体系标注，同时展示等级标签与浅白描述；存款类条目不逐条标注（在类型级统一标注"低"，见 2.4） |
| 期限结构 | 是 | 该条目对应的约定期限档（如 3 个月 / 6 个月 / 1 年）；同一产品存在多档期限时，按一档期限一条条目组织 [是否多档合并展示 TBD] |

| 信息更新日期 | 是 | 字段定义见 4.2 |

新增字段须经评审 [是否预留字段扩展机制 TBD]。

### 3.2 "业绩比较基准"用词规范

**规则**：银行理财产品条目只使用"业绩比较基准"一词，禁止出现"预期收益率"表述。依据：行业规范已要求理财产品不得以"预期收益率"等方式暗示承诺收益，应以"业绩比较基准"等表述展示参考目标 [所引用的具体规范名称 TBD]。

**小白向解释（建议稿，最终文案 [TBD]）**——两者的区别：

- **预期收益率**（本模块不使用）：读起来像"大概能拿到这么多"，容易被理解为接近承诺的收益；
- **业绩比较基准**：产品管理人给出的参考目标，实际到期收益可能高于、也可能低于该值，不构成任何承诺。

差异的本质：银行理财不是存款、不保本，收益随投资表现波动；判断"本金是否有保障"应看产品性质与存款保险制度的保障范围（见 5.2），而非看展示的收益数字。

**展示形态**：字段名固定展示为"业绩比较基准"，首次出现处附上述浅白解释（遵循 [01](01-产品定位与整体方案.md) 约束 5）。

**异常场景**：

| 异常场景 | 产品行为 |
|---|---|
| 银行公示使用其他表述（如"业绩基准"等） | 一律归入"业绩比较基准"字段，并在条目内注明原始表述 [原始表述的呈现方式 TBD] |
| 数值未能核实 | 展示"待核实"占位（见 3.3），不填入任何数值 |

### 3.3 条目展示规则

**布局**：类型列表页中每条条目为一张卡片或一行：主体展示发行银行与产品类型，字段组展示期限结构、起购金额、利率或业绩比较基准、风险等级（理财类）；底部固定展示信息来源与信息更新日期。

**触发**：进入类型列表页即展示全部（或经筛选的）条目；条目无独立详情页 [Assumption, TBD：是否支持点击展开完整字段]。

**处理规则**：字段值未核实或缺失时，该字段展示"待核实"占位符 [占位样式 TBD]，绝不填入猜测数值；其余字段正常展示，互不影响。

**结果与状态变化**：条目内容只在人工整理更新时变化（见第 4 章）；用户浏览行为不改变条目任何内容。

### 3.4 条目状态

产品信息条目存在以下可观察状态：

| 状态 | 表现 |
|---|---|
| 正常 | 全部字段有核实值，展示信息更新日期 |
| 待补充 | 存在未核实字段：该字段展示"待核实"占位，其余字段正常 |
| 待复核 | 超过复核周期未更新 [周期判定规则 TBD，见 4.4]：条目展示"信息较旧，请以银行官方信息为准"标记 [标记样式 TBD] |

状态由信息整理过程驱动，无任何用户可操作的状态变更入口。

**异常场景**：

| 异常场景 | 产品行为 |
|---|---|
| 条目整体信息缺失（仅知该银行有此类型产品） | 以银行 × 类型为粒度展示占位条目，全部数值字段标"待核实" [是否提供此粒度的占位条目 TBD] |
| 条目字段之间存在矛盾（如来源页信息自相矛盾） | 暂不收录该条目，待人工核实后再入库 |

## 4. 信息时效性声明与更新机制

### 4.1 功能目的

让用户随时知道"我看到的信息有多新、可信度如何"，避免把人工整理的滞后信息误当作银行当前公示——这是纯人工整理模式（见 1.2）下必须内建的机制。

### 4.2 "信息更新日期"字段

| 项目 | 定义 |
|---|---|
| 字段 | 信息更新日期 |
| 含义 | 最近一次人工核对并整理该条目的日期 |
| 与银行官方发布的关系 | 不是银行官方发布日期：银行公示变更后，本字段只有在人工复核后才更新，因此可能晚于银行实际变更 |
| 展示位置 | 每条条目底部固定展示；银行条目展示该行全部条目的最近复核日期（见 2.3） |

### 4.3 页面时效性声明文案（建议稿）

模块落地页与各类型列表页的显著位置（页面顶部、常驻可见）展示以下声明 [最终文案 TBD]：

> 本模块信息由人工整理自银行公开渠道（银行官网、官方 App 公示），非实时同步；各条目的"信息更新日期"为最近一次人工核对时间。信息可能滞后于银行最新公示，请以银行官方信息为准；标注"待核实"的字段尚未完成核实，不作参考。

### 4.4 更新机制

| 项目 | 规则 |
|---|---|
| 更新方式 | 人工不定期整理：新增条目、复核既有条目、修订失效信息 |
| 更新频率 | [TBD，产品运营决策：需在人工成本与信息时效之间权衡后确定] |
| 复核规则 | 超过 [周期 TBD] 未复核的条目进入"待复核"状态（见 3.4） |
| 与官方不一致的处理 | 一律以银行官方信息为准（1.2 权威声明）；本产品不承诺实时纠错 |
| 用户纠错 | 不提供在线纠错反馈通道，页面以 4.3 声明引导用户以银行官方为准 [Assumption, TBD：理由是产品为本地优先形态（[01](01-产品定位与整体方案.md) 约束 3），云同步仅覆盖数据存储、不承载在线反馈] |

**因果说明**：更新频率只显式声明为"人工不定期"而不承诺固定值，因为信息由人工整理、频率受人力波动影响；若对外承诺固定频率（如"每月更新"），人力不足时即形成违背承诺的事实，反而损害可信度。因此产品只展示"每条目的最近核对日期"这一可观察事实（4.2），不展示任何承诺性频率表述。

### 4.5 异常场景

| 异常场景 | 产品行为 |
|---|---|
| 条目超过复核周期未更新 | 进入"待复核"状态，展示"信息较旧"标记（见 3.4） |
| 条目对应产品疑似下线 | 人工复核确认前保留条目并标"待复核"；确认下线后移除该条目 [是否保留"已下线"痕迹 TBD] |
| 银行公示频繁变动（如利率调整） | 不追实时变动，以最近一次人工核对为准，依赖 4.3 声明兜底 |
